Architecture

MetricMind follows a layered architecture that combines cloud data warehousing, semantic modeling, AI-driven natural language understanding, and an interactive web interface to deliver governed business intelligence. Instead of allowing the AI model to generate SQL directly, every user query is mapped to predefined business measures and dimensions in Cube.dev. This ensures consistent, transparent, and reliable analytical results while preventing SQL hallucinations.

The overall architecture consists of five major components: Snowflake, dbt, Cube.dev, FastAPI, and Next.js with LangChain. Each component performs a dedicated role within the analytics pipeline, enabling modular development and easy maintenance.


Architecture Flow
Snowflake (Raw Data Warehouse)
            │
            ▼
dbt (Data Cleaning & Staging Models)
            │
            ▼
Cube.dev (Semantic Layer)
            │
            ▼
FastAPI Backend (/ask, /query)
            │
            ▼
Next.js Dashboard + Chat UI (LangChain)
            │
            ▼
Business User


Snowflake

Snowflake is the central cloud-based data warehouse that stores both raw and cleaned business data. It serves as the primary source of information for analytical queries. Cleaned order data is maintained in the staging schema and is accessed only through the semantic layer, ensuring consistency and security.

Responsibilities
Stores raw and cleaned datasets.
Executes SQL queries generated by Cube.dev.
Supports scalable analytical processing.
Maintains enterprise-grade data storage.

dbt (Data Build Tool)

dbt is responsible for transforming raw data into analytics-ready staging models. It applies data cleaning, validation, and testing before the data becomes available to downstream components.

Responsibilities
Cleans and transforms raw datasets.
Creates staging models.
Performs automated data quality tests.
Ensures reliable and validated data.

Cube.dev (Semantic Layer)

Cube.dev forms the semantic layer of MetricMind. It defines governed business measures such as total_sales, profit_margin, and order_count, along with dimensions like category, region, and order_date. Instead of querying database tables directly, the AI maps user questions to these predefined semantic models.

Responsibilities

Defines business measures and dimensions.
Generates optimized SQL queries.
Enforces business rules and governance.
Applies a maximum query limit of 5,000 rows.
Ensures consistent analytical results.

FastAPI Backend

The FastAPI backend acts as the communication layer between the frontend and Cube.dev. It receives user questions, processes semantic queries, retrieves results from Cube.dev, and returns both the analytical results and generated SQL for transparency.

Responsibilities

Handles REST API requests.
Processes natural language queries.
Connects with Cube.dev.
Returns analytical results.
Provides SQL transparency.

Next.js Frontend (LangChain)

The frontend provides an intuitive chat-based Business Intelligence interface. LangChain interprets natural language questions and maps them to Cube.dev semantic measures and dimensions before the backend executes the query.

Responsibilities

Provides chat interface and dashboard.
Displays KPI cards and dynamic charts.
Supports interactive filtering.
Shows generated SQL using the View SQL feature.
Presents governed analytical insights.

Data Flow

The data processing pipeline begins with raw business data stored in Snowflake. dbt cleans and validates this data before publishing staging models. Cube.dev builds a governed semantic layer on top of these models. When a user submits a question, the frontend sends the request to the FastAPI backend. LangChain interprets the query, maps it to Cube.dev measures and dimensions, and Cube.dev generates optimized SQL. Snowflake executes the SQL query, and the results are returned to the frontend as charts, KPI cards, and SQL for complete transparency.

Data Flow Steps

Raw data is stored in Snowflake.
dbt transforms and validates the data.
Cube.dev exposes governed semantic models.
User submits a natural language query.
FastAPI processes the request.
LangChain maps the query to semantic measures.
Cube.dev generates optimized SQL.
Snowflake executes the query.
Results are returned to the frontend.
Dashboard displays analytics and generated SQL.
Governance

MetricMind is designed around a governed semantic architecture rather than a text-to-SQL approach. This ensures that every analytical result is consistent, repeatable, and transparent.

Governance Features

Predefined business measures and dimensions.
Hallucination-free semantic query mapping.
Maximum query limit of 5,000 rows.
Consistency testing for repeated queries.
SQL transparency for every response.
Reliable and governed business metrics.


Repository Structure

project-1-new-extracted/	Next.js frontend with chat interface, dashboard, and LangChain integration.


Technology Stack

Frontend: Next.js, React, TypeScript
Backend: FastAPI
AI Orchestration: LangChain
Semantic Layer: Cube.dev
Data Transformation: dbt
Database: Snowflake
Containerization: Docker
API Communication: REST APIs


Architectural Advantages

Governed semantic query processing.
Hallucination-free business analytics.
Consistent business metrics.
Transparent SQL generation.
Modular and scalable architecture.
Automated data validation using dbt.
Enterprise-ready governance and reliability.
Easy integration between frontend, backend, and data warehouse.

conclusion

MetricMind adopts a modern, semantic-driven architecture that combines Snowflake, dbt, Cube.dev, FastAPI, LangChain, and Next.js to deliver reliable and governed business intelligence. By routing every natural language query through a predefined semantic layer instead of generating arbitrary SQL, the platform ensures consistent, transparent, and hallucination-free analytical results. Its modular design enables scalability, maintainability, and seamless integration across all components, making MetricMind a robust solution for enterprise-grade AI-powered analytics.
